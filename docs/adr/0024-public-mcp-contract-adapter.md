# ADR 0024: Public MCP contract adapter

Date: 2026-07-23

Status: Accepted

## Context

Diffuse's initial MCP tools used numeric repository IDs and snake_case
parameters. That is convenient for its internal database, but Greptile's
documented public MCP contract identifies repositories by `name`, `remote`,
`defaultBranch`, and optional `remoteUrl`, uses camelCase fields such as
`prNumber`, and documents both pull-request list names plus
`search_greptile_comments`.

Merely advertising aliased JSON Schema properties is insufficient. FastMCP
invokes the Python function using the wire-name keyword, so an alias can appear
valid during discovery and still fail when called. Repository descriptor
resolution must also enforce token claims without revealing whether an
unauthorized repository exists.

Public references:

- <https://www.greptile.com/docs/mcp/tool-reference>
- <https://www.greptile.com/docs/mcp/comment-resolution>
- <https://www.greptile.com/docs/mcp/reports>

## Decision

- Keep camelCase and vendor-compatible names in thin MCP boundary functions;
  translate immediately to Diffuse-native snake_case storage calls.
- Advertise and execute both `list_merge_requests` and `list_pull_requests`.
- Resolve a complete repository descriptor to an internal repository ID in the
  same database query that applies the authenticated token's repository
  claims. Reject partial descriptors, mixed numeric/descriptor identity, and
  unauthorized or nonexistent targets with the same error.
- Default an omitted `remoteUrl` to the public GitHub or GitLab origin, while
  requiring it for a different self-hosted origin to resolve.
- Expose `list_merge_request_comments` from the latest applied finding in each
  durable lineage and include the external root comment ID when one exists.
- Expose `search_greptile_comments` as the public organization-wide name while
  retaining `search_review_comments` as a Diffuse extension with repository
  filtering and pagination.
- Treat the compatibility `greptileGenerated` filter and response field as
  “generated by this endpoint's configured review system.” Also return
  `diffuseGenerated: true` so provenance is unambiguous.
- Continue deriving addressed state from published finding-lineage
  transitions. MCP does not claim that changing a response field or applying a
  local edit has resolved the remote review thread.

## Consequences

Existing MCP-capable agents can use the documented PR, review, and comment
parameter shapes against a self-hosted Diffuse server. The adapter does not
duplicate review data, bypass repository scopes, trust a stale branch name, or
introduce Greptile as a runtime dependency.

Organization-scoped implicit context creation still differs because Diffuse
does not yet have the organization/team RBAC model. GitLab review triggers,
and first-class analytics remain future work. Revision-safe agent handoff is
addressed by ADR 0025; Diffuse-native source-linked search and grounded
repository Q&A are addressed by ADR 0026; audited operator-context mutation is
addressed by ADR 0027.
